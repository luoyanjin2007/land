# 代码地图

> 目标：给定一个功能名，能立刻定位到文件与符号。行数为 v36 时快照。

## 一、总体架构

- 12 个普通脚本（非 module），在 `index.html` 中**按依赖顺序**加载，共享全局命名空间；
  后面的文件可直接引用前面的全局对象。无打包器、无类型系统、无运行时第三方依赖。
- 世界是**按需确定性生成**的：不预生成整张地图，`World.tileAt(x,y)` 在首次访问某格时
  由分层 value noise + 城市规则算出地形；种子固定 `20260901`，同种子结果逐像素可复现。
- 渲染用**分块烘焙缓存**：16×16 格烤成一张离屏 canvas，配合画家算法/y 排序遮挡。
- 主循环：`main.js` 的 rAF，dt 上限 0.05。

## 三、world.js 关键地图

- `CITIES`：六城坐标/尺寸/等级，当前值：

  | 城 | 坐标(x,y) | 规模(w×h) | tier |
  |---|---|---|---|
  | 圣魂村 | 260,140 | 20×16 | village |
  | 诺丁城 | 380,210 | 40×32 | town |
  | 史莱克学院 | 540,280 | 70×55 | city |
  | 索托城 | 470,420 | 70×55 | city |
  | 武魂城 | 700,560 | 160×140 | holy |
  | 星罗城 | 740,780 | 110×90 | capital |

  另有 `godIsland`（120,450 海神岛）、`forest`（星斗大森林，cx640,cy520 三层半径）。
  出生点 = 圣魂村主街。
- 六个独立城市生成函数：`genShenghunVillage / genNuodingCity / genShrekAcademy /
  genSuotoCity / genXingluoCity / genWuhunCity`（映射表 `CITY_GENERATORS`）。
- 城市基建 helper：`fillRect`、`roadLine`、`cityWalls`（带门洞）、`placeBuilding`
  （登记大图、偶数宽 x 对齐）、`placeHouse2x2`、`fillBlock2x2`、`yardAroundHouses`、`cityInfill`。
- 道路：`carveRoad` BFS 双模式（陆地优先，允许水时架桥兜底）；`generateRoads`
  连接 `[0,1][1,2][2,3][3,5][5,4][1,3]`；`placeScenicLakes` 在远段路旁放 3 个风景湖。
- 地形链：`tileAt` →（缓存 `_tc`，仅生成后启用）→ `computeTile`：
  城内 → PATH 道路 → 湖 → 城市覆盖（`cityLakeLift` 超椭圆 p=3）→ `naturalTile`。
- `naturalTile` 负责：海神岛、东西海岸、北天山、南海与南沙漠、星斗森林三层、
  基础噪声 `e=n1*.55+n2*.3+n3*.15`（水<0.28 / 沙<0.31 / 森林>0.72 / 山>0.60 等）。
- `walkable`：阻挡 MOUNTAIN/HOUSE/WALL/FOUNTAIN/TEMPLE/PALACE/COLLEGE/FLOWER；水可游。
- RNG/噪声：`mulberry32`、`makeNoiseLayer`（双线性+smoothstep）。

## 四、render.js 关键地图

- 贴图清单：`SPRITE_LIST`（人物帧/游泳帧/魂兽/房屋/树/地块/草丛 4 变体）、
  `TILE_IMG`（同类地块多变体池）、`BUILDING_LIST`（farmhut/house/temple-s·m·l/
  college-s·l/palace/arena 共 9 种大图）。
- `loadSprites`：魂兽与建筑是 JPG，经 `removeWhiteBg` / `trimWhiteSprite`
  （泛洪抠外部白，保留内部白墙）处理。
- `spritesReady`：首屏只需"会进 chunk 烘焙的贴图 + b-farmhut + b-temple-small"，
  人物动作图后台加载。
- 缓存：`getChunk`（chunkCache）、`getWaterMask`（maskCache）、草丛 `getTuftLayer`
  （tuftCache）；`evictFar` 门槛 30、keep 3，最多 49 块。
- 帧编排：`draw` → 地面 `drawGroundInto` → 物件 `drawPropsInto` →
  建筑 `drawBuildings(front)` 前后景分层 → 草丛 `drawNearTufts`（人物周围洞）→
  人物/魂兽 → 水面特效/雨/HUD。
- 草丛系统：`tuftAt(wx,wy)` 确定性决定每格草丛有无/变体/高度（静态层与逐帧路径
  共用，保证逐像素一致）；洞内每帧用 `setTransform(1,0,bend/gh,1,…)` 作风摆+人物拨。
- 验收 UI：性能面板（P 键；B 空跑；面板打开时 1~5 切分层）、`BUILD` 版本戳。
- HUD：`drawHUD`（天/时段/坐标/城市/移动状态，时段取自 `Ambience.nightLevel`）、
  `drawBars`、`drawSkillBar`、`drawMinimap`（雷达 + 迷雾遮黑 + 城市名）。
- 程序化兜底：房屋/殿/宫/学院/花圃在贴图缺失时有 canvas 手绘版本，保证不白屏。

## 五、战斗/养成数据流（改数值时看这里）

- 数值源头只有两处：`souls.js`（武魂相关）、`entities.js` 的 `MONSTER_TYPES`
  （魂兽相关）。当前全部是试玩占位值，平衡待试玩反馈。
- `Player.awaken(soulId)` 用 SOULS 初始化属性与 `Combat.reset()`；
  `Combat.addExp` 处理升级循环、属性成长、魂环数重算；升级经验 `8+lv*4`。
- 解锁：技能解锁等级 `SKILL_UNLOCK = [1,3,5,8]`；魂环目前随等级自动获得。
- 技能形状类型（combat.js `cast(i)` 分派）：cone / shield / nova / smite /
  root / zone / line。

## 六、assets/ 分类

- `assets/sprites/`：运行时贴图，全部会被部署。`buildings/` 子目录是 9 张建筑 JPG。
- `assets/*.jpeg`：
  - 运行时使用：`圣魂村-俯视地图.jpeg`（开场背景）、`天空云影-裁剪.jpeg`（水面反射）；
  - 其余（地面/建筑/草丛/角色等"图集".jpeg）是 `slice.js` 的**切图原料**，运行时从不下载，
    CI 也不部署。删除只影响以后重新切图，故保留。

## 七、tools/ 分类（node 脚本，用法见各文件头注释）

- `verify/`：世界生成验收，独立可跑（内部 eval world.js，种子 20260901）：
  - `road_check.js` 六段道路连通性与覆盖格数
  - `connectivity_check.js` 不借路、纯自然地形能否在城门间互通
  - `bridge_check.js` / `bridge_debug.js` 桥格统计与成因
  - `threshold_test.js` 山峰阈值扫描（M2 历史工具）
- `asset-pipeline/`：`slice.js`（图集→sprites，白底转透明）、
  `make_flower_overlay.js`（花地块抠绿底做覆盖层）、`preview_trim.js`（抠白效果肉眼验收图，输出到 `previews/`）
- `screenshots/shot.cjs`：无头 Edge + CDP，自动过开场/觉醒后把人物送到各地标点
  截图到 `shots/`（本机 Edge 路径写死，需先在 8080 起静态服务）。
- `previews/` 与 `shots/` 均为本地产物，已 gitignore。

## 八、跨文件契约（改动时别破坏）

1. `index.html` 的脚本**顺序与路径**必须保持与依赖一致；src/ 目录不得随意改名
   （file:// 直接引用，且 CI 按 `src/*.js` 拷贝）。
2. 地块编号 0~15 为既有约定，新类型从 16 起；新增不可通行类型要同步检查
   `walkable`、实体 `landAt`、渲染 COLORS/贴图分支。
3. 草丛静态层与逐帧层共用 `tuftAt`，任何草丛放置规则改动必须两边同时成立，否则撕裂。
4. 任何 src 代码改动后：`index.html` 全部 `?v=N` + `Render.BUILD` 要同时 +1
   （file:// 与浏览器缓存激进，不升版本会新旧代码混杂）。
