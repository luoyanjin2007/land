# AI 行为手册

> 每次会话开工先读本页。目的：用固定动作回答三个问题——
> **① 现在做到哪了？② 接下来做什么？③ 看哪些文件/跑哪些命令能验证？**
> 用户的固定要求：**任何操作直接做，不先问许可；有风险边做边告知。
> 玩法/剧情/系统方向选择一律用 AskUserQuestion 选项框（带 preview）。**

2. `docs/02-当前进度.md`：系统 → 版本 → 文件 → **验证方法**对照表。
3. 线上状态：master 部署正式站、preview 部署预览站；`master..preview` 即"已验收待发布"差异。
4. 代码事实以当前代码为准：memory 与 docs 可能滞后，关键结论动手前用
   Grep/Read 复核（文件:行号可能已漂移）。

## 2. 查"未来计划"

1. `docs/03-未来计划.md`（P1~P5 + 候选 + 已否决方案）。
2. 用户级 memory `…\memory\todos.md` 是同一内容的镜像；改计划两处同步。
3. 长期设计初衷看 `docs/斗罗大世界规划.md`；原著资料看 `docs/斗罗大陆背景整理.md`。

## 3. 验证"做完没有"——系统对号入座

| 改动领域 | 自动验证（必跑） | 人工/截图验证 |
|---|---|---|
| 地形/世界生成 | `node tools/verify/road_check.js`、`connectivity_check.js`、`bridge_check.js` | 跑图 |
| 山峰/噪声阈值 | `node tools/verify/threshold_test.js` | — |
| 建筑/城市布局 | `node --check src/world.js` | `tools/screenshots/shot.cjs` 截图后 Read 看图 |
| 建筑抠白底 | — | `node tools/asset-pipeline/preview_trim.js <名>` 再 Read 产物 |
| 切图/花覆盖层 | 对应 asset-pipeline 脚本 | Read 输出 PNG |
| 战斗/魂技/魂兽 | `node --check` + 浏览器实测 | 与怪交战看技能/飘字/CD |
| 性能 | P 开面板看帧时；B 空跑量地板 | 密林/密草现场体感 |
| 昼夜/天气/HUD | — | 等一个昼夜，文字与天色对读 |
| 任何改动 | 全部相关文件 `node --check` | 视觉结论必须自己截图亲眼确认，不要只凭代码推断 |

游戏内调试键：`P` 性能面板（分层计时/版本戳）、面板打开时 `B` 空跑、`1~5` 切分层、
`M` 大地图。截图脚本需要先在 8080 起静态服务（`npx http-server -p 8080` 之类）。

## 4. 改代码铁律

1. **编辑 JS 用 Edit/Write 工具，不用 bash heredoc/`node -e`**：Git Bash 会吞模板字符串
   `` `${...}` ``，曾导致替换"静默成功"实则没改。
2. 任何 src 改动，版本号三处一起 +1：`index.html` 全部 12 个 `?v=N`、`Render.BUILD`、
   提交信息前缀 `vN`。不升版本会因 file:///浏览器缓存出现新旧代码混杂（历史上多次踩中）。
3. 脚本加载顺序与 `src/` 路径不可随意动（见 01 文档第八节契约）。
4. 新增地块类型：编号从 16 起，并同步 `walkable`、实体 `landAt`、渲染分支。
5. 草丛规则改动必须保证静态层与逐帧层共用的 `tuftAt` 两边同时成立。
6. 数值源头只在 `souls.js` 与 `entities.js MONSTER_TYPES`；当前为占位值，调平衡要标注。
7. `.env` 含密钥，已 gitignore，**绝不提交/部署**；不要把它的内容写进任何文档或输出。

## 5. 提交与发布管线

- 分支：日常在 `preview`；正式发布合并 `master`（fast-forward 习惯）。归档分支不部署。
- CI（`.github/workflows/deploy.yml`）push master/preview 触发，部署内容**仅**
  `index.html + src/*.js + assets/sprites/ + 两张 JPEG`；tools/docs 不部署。
- 发布节奏（既定）：
  1. 在 preview 提交 → `git -c http.proxy=http://127.0.0.1:31181 push`（需 DevSidecar 代理）；
  2. https://preview.land-8aq.pages.dev 试玩/截图，确认只能靠眼睛验的东西；
  3. 验收后合 master 并同样走代理 push → https://land-8aq.pages.dev 生效。
- commit message 末尾加：`Co-Authored-By: Claude Code <noreply@anthropic.com>`。
- push 是对外动作：按既定节奏可直接推 preview；合并 master 属正式发布，
  遵循用户当次指示。

## 6. 本机环境坑（详见 memory game19-env-quirks）

- 无 `jq`；解析 JSON 用 node。
- `/tmp` 在不同工具下指向不一致；临时文件放项目内或用绝对路径。
- `runPlaywrightCode` MCP 在本机失效；浏览器验证用截图脚本或浏览器 MCP 页面工具。
- curl 传 JSON body 的引号在 Git Bash 下易踩坑；需要时写文件再 `--data @file`。
- GitHub API 凭据走 Windows 凭据管理器（`git credential fill`），不要让用户手贴 token。
